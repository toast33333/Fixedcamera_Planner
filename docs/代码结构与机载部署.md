# 当前代码结构与机载部署边界

## 研发仓库结构

| 路径 | 作用 | 是否进入机载包 |
|---|---|---|
| `src/detection_msgs` | RK3588目标检测、带采集时间戳的检测消息 | 仅当前入口、消息、一个模型 |
| `src/kcf_msgs` | 旧KCF消息和历史跟踪代码 | 仅保留 `Bbox.msg` 编译兼容 |
| `src/png_planner` | 固定相机控制、雷达抵近以及历史控制器/仿真节点 | 仅当前两个控制节点及配置 |
| `tools/field` | 三种外场视觉控制启动脚本 | 是 |
| `tools/simulation` | 批量仿真、分析、汇总 | 否 |
| `tests` | 研发回归测试 | 否 |
| `docs` | 设计与实验文档 | 否 |
| `third_party/INSLIB` | 可选导航算法源码 | 默认PX4/MAVROS机载包不带 |

## 当前生产链路

```text
USB相机
  -> RK3588/RKNN检测
  -> /object_detections（图像采集时间戳）
  -> fixed_camera_ibvs（视觉控制候选）
  -> radar_approach_handover（仅完整抵近任务使用，交接后转发视觉指令）
  -> /mavros/setpoint_velocity/cmd_vel
  -> PX4
```

无雷达直接视觉试验时，`fixed_camera_ibvs` 直接发布 MAVROS 速度指令；完整任务中，
它只发布候选指令，由 `radar_approach_handover` 独占最终 MAVROS 指令话题，避免两个
节点同时控制。

## 已判定为不应部署的内容

- 名称含 `multisim`、`sitl` 的 launch、节点和脚本；
- `target_sitl_sim.cpp`、`px4_multisim_experiment.py` 与随机扰动仿真脚本；
- 历史 `rp_*`、`rpy_*`、云台串口与键盘测试控制器；
- `ros1Main_old.py`、`ros1Func_old.py`、重复的录像入口和备份文件；
- KCF目录中重复的检测模型；
- 未被当前视觉入口引用的备用 RKNN 模型；
- 仿真结果、录屏、PPT、日志、测试与分析工具；
- 默认PX4/MAVROS状态源不用到的 INSLIB 源码。

这些文件可以继续留在研发仓库用于追溯和复现实验，但机载包必须通过白名单导出：

```bash
python3 tools/deployment/export_airborne_workspace.py \
  /tmp/fixed_camera_airborne_ws \
  --archive /tmp/fixed_camera_airborne_ws.tar.gz
```

GitHub 的 `airborne` 分支由同一白名单生成，飞机端可直接浅克隆该分支；`main`
是研发分支，不应整仓复制到飞机。

详细上机步骤见 `deploy/airborne/README.md`。
